## Meta-Patterns appended (Sprint 5)
- **Driver semantics matter for session-scoped DB primitives**: Postgres advisory locks are session-scoped. The Neon HTTP driver opens a fresh session per query, so a lock acquired via `neon()` auto-releases the moment the acquire query returns. Same class of issue applies to: temp tables, prepared statements, multi-query transactions, advisory locks, listen/notify, server-side cursors. Rule: any DB feature that depends on session state must use `Pool` (WebSocket) from `@neondatabase/serverless`, sharing a single `client` across the session-scoped pair. Documented as a Gotcha; the lead caught this via plan_approval review.
- **Plan approval is only as strong as teammate compliance**: F-009 had `require_plan_approval: true` and the lead caught the lock-correctness blocker in the review. The teammate received the SendMessage but proceeded with the broken approach anyway, citing "multiple idle hooks with no lead response" — even though the response had been sent. Either the message was filtered out by the agent, or the teammate's idle-recovery path bypasses the wait-for-approval state. Sprint 6 should: (a) make spawn prompts more explicit ("if you ever doubt whether you got the approval response, SendMessage team-lead asking BEFORE writing code"), (b) consider adding a hook that blocks file edits in the teammate's scope until a `.harness/teammate-<name>-approved.flag` file exists.
- **Bundled commits across teammates lose per-feature provenance**: the F-011 logging teammate ran `git add -A` and committed BOTH F-011 and F-009 files in one `feat(F-011)` commit. Per-feature commit boundary lost; reverting one feature's work now requires file-level surgery. Spawn prompts should specify "commit only files in your scope" explicitly. Or add a pre-commit hook that warns when staged files cross teammate scopes (per `.harness/features.json` scope arrays).
- **Lead-side fixes are sometimes faster than another correction cycle**: F-009's lock fix was ~30 LOC source + ~30 LOC test changes. Sending the orchestrator back for a correction cycle would have cost a fresh-spawn or wake-up + context reload + their TDD cycle. Doing it directly saved time and preserved the 100%-coverage achievement. Pattern: when the fix is small, well-understood, and isolated, the lead exits plan mode and applies it directly with a separate `fix(FXXX)` commit. When the fix touches multiple modules or requires reasoning the teammate hasn't done yet, send back.
